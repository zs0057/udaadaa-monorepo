# Subagent Policy

## 목적

서브에이전트를 단순히 많이 사용하는 것이 아니라, 독립적인 작업을 병렬로 처리하여 탐색 속도와 검토 품질을 높이는 데 사용한다.

## 기본 원칙

- 범위가 작거나 순차적인 작업은 메인 에이전트가 직접 수행한다.
- 서로 독립된 하위 작업이 두 개 이상일 때만 서브에이전트 사용을 고려한다.
- 읽기·조사·테스트·검토 작업을 우선적으로 위임한다.
- 같은 파일을 여러 에이전트가 동시에 수정하지 않는다.
- 서브에이전트의 결과는 제안과 근거이며, 최종 결정은 메인 에이전트가 내린다.
- 사용자가 에이전트 사용을 금지하거나 범위를 제한하면 해당 요청을 우선한다.

## 역할

### 메인 에이전트

- 사용자 요구사항과 전체 컨텍스트 관리
- 하위 작업의 범위와 완료 기준 정의
- 에이전트 간 중복과 충돌 방지
- 결과 비교 및 통합
- 최종 설계 결정과 검증

### 서브에이전트

- 할당된 범위만 조사하거나 구현
- 코드와 문서의 근거 위치 기록
- 확인한 사실과 추론 구분
- 발견한 위험과 미확인 사항 보고
- 정해진 형식으로 결과 요약

## 사용하기 좋은 작업

- Flutter 기능, Supabase Edge Function, 데이터베이스 의존성의 병렬 조사
- 회원·챌린지·기록·채팅 등 서로 다른 도메인의 현행 구조 분석
- 보안·테스트·유지보수성 관점의 독립적인 코드 리뷰
- 서로 독립적인 테스트 묶음 실행과 실패 원인 분석
- 여러 아키텍처 후보의 장단점 조사
- 많은 로그나 문서를 범위별로 나누어 요약하는 작업

## 사용하지 않을 작업

- 하나의 파일을 여러 에이전트가 동시에 수정해야 하는 작업
- 앞 단계 결과가 있어야 다음 단계를 시작할 수 있는 작업
- 단순한 문구 수정이나 작은 버그 수정
- 사용자와 합의하지 않은 최종 아키텍처 확정
- 결제·정산·권한 규칙을 검증 없이 자동 결정하는 작업
- 작업 분배와 결과 통합 비용이 직접 수행 비용보다 큰 작업

## 위임 시 포함할 정보

```text
목표: 무엇을 확인하거나 완성할 것인가
범위: 담당 파일과 제외할 파일
제약: 수정 가능 여부와 지켜야 할 규칙
산출물: 결과 형식과 반드시 포함할 근거
완료 조건: 언제 작업이 끝났다고 판단할 것인가
```

## 결과 통합 체크리스트

- 각 결과에 파일 또는 코드 근거가 있는가?
- 에이전트 간 결과가 충돌하지 않는가?
- 조사 범위가 누락되거나 중복되지 않았는가?
- 추측이 사실처럼 기록되지 않았는가?
- 최종 결과를 메인 에이전트가 다시 검증했는가?
